
Non-functional requirements define the quality attributes of the booking system. Unlike functional requirements, they describe how the system should perform, including its usability, security, reliability, maintainability, performance and accessibility.

## 1. Usability
| ID     | Requirement                                                                      |
| ------ | -------------------------------------------------------------------------------- |
| NFR1.1 | The system shall provide an intuitive and user-friendly interface.               |
| NFR1.2 | The system shall be responsive and usable on desktop, tablet and mobile devices. |
| NFR1.3 | The system shall provide clear feedback following user actions.                  |

## 2. Performance

| ID     | Requirement                                                               |
| ------ | ------------------------------------------------------------------------- |
| NFR2.1 | The system shall load pages within an acceptable time under normal usage. |
| NFR2.2 | The system shall process booking requests efficiently.                    |

## 3. Security
| ID     | Requirement                                           |
| ------ | ----------------------------------------------------- |
| NFR3.1 | The system shall store user data securely.            |
| NFR3.2 | The system shall encrypt administrator passwords.     |
| NFR3.3 | The system shall protect against unauthorised access. |

## 4. Reliability

| ID     | Requirement                                                                |
| ------ | -------------------------------------------------------------------------- |
| NFR4.1 | The system shall maintain the integrity of booking data.                   |
| NFR4.2 | The system shall recover gracefully from unexpected errors where possible. |

## 5. Maintainability
| ID     | Requirement                                                         |
| ------ | ------------------------------------------------------------------- |
| NFR5.1 | The system shall use clear and consistent code formatting.          |
| NFR5.2 | The system shall be fully documented to support future maintenance. |
| NFR5.3 | The source code shall be managed using Git and GitHub.              |

## 6. Accessibility
| ID     | Requirement                                                                        |
| ------ | ---------------------------------------------------------------------------------- |
| NFR6.1 | The system shall use appropriate colour contrast for readability.                  |
| NFR6.2 | The system shall support keyboard navigation where practical.                      |
| NFR6.3 | The system shall provide meaningful alternative text for images where appropriate. |
